# G750 Boost — 骁龙 GPU 游戏地板档位模块

**作者**: 雨色
**版本**: v2.1.0
**适配**: SM8650 (8 Gen3 / Adreno 750) · SM8750 (8 Elite / Adreno 830) · SM8850 (8 Elite Gen5 / Adreno 840)
**兼容**: KernelSU / Magisk / APatch

---

## 一句话介绍

**游戏运行时把 GPU 最低频率（地板）抬到你设置的档位，最高频率保持不变，让系统在这个区间内自动调频；退出游戏 8 秒后自动恢复系统默认。**

---

## 核心概念：设置的是「最低值」，最高值不动

这是本模块最关键的语义，用一张图说明：

```text
             最高频率（默认不动，如 903MHz）
                    ▲
                    │   ← 系统 governor 在此区间内自动调频
                    │       （游戏有负载时自动往上冲）
   你设置的档位 ────┼───  ← 模块只把「地板」抬到这里（如 680MHz）
                    │
                    │   ← 空闲时系统可降到更低
             最低频率
```

- ✅ **你设置的 = 最低频率（地板）**
- ✅ **最高频率默认不动**（保持硬件最高档）
- ✅ **系统 governor 在地板以上自由调频**

| 场景 | 效果 |
|---|---|
| 空闲 / 不玩游戏 | 恢复系统默认地板（约 231MHz / 160MHz） |
| 玩游戏（前台/后台/小窗） | 地板抬到目标值，上限不变，系统往高处自动调频 |

**不会锁死频率**——这正是"最低频率往上自动调整"的设计目的：既不因降频掉帧，也不浪费功耗。

---

## 为什么需要它

手机系统的 GPU governor（高通 `msm-adreno-tz`）为了省电，会在 GPU 负载波动时主动降频。游戏场景下会导致帧率抖动、偶发卡顿。本模块在**检测到目标游戏运行时**把 GPU **地板**抬高，让 governor 不会降到令人不适的低频，同时**不干预上限**，功耗增加可控。

---

## v2.1.0 核心特性

| 特性 | 说明 |
|---|---|
| **min_pwrlevel 档位接管** | 采用比 `min_freq` 更硬的内核档位接口；实测 13 分钟+ 零覆盖 |
| **max_pwrlevel 上限接管** | 上限也写入内核节点，常驻保护，防止其他模块/应用拉低上限 |
| **三平台自适配** | SM8650 / SM8750 / SM8850，运行时探测平台与频率表，不硬编码 |
| **频率表多路径识别** | 8g3 → `devfreq/available_frequencies`；8e5 → `gpu_available_frequencies`；自动归一化 Hz/MHz |
| **GPU 型号优先识别** | 以 `gpu_model`（Adreno750/830/840）为第一判据，不受厂商 `ro.soc.model` 命名污染 |
| **按平台区分安装** | 安装时自动识别处理器并显示平台信息；未适配平台直接拒绝安装 |
| **WebUI 自定义档位** | 从设备真实频率表生成"地板 + 上限"两个下拉框，5 秒内生效 |
| **双事件监听** | `am_proc_start`（启动）+ `am_proc_died`（退出），响应 < 100ms，5 秒校验兜底 |
| **最小开销** | 运行中只"读一次"校验，偏离才重写，不做盲目轮询 |
| **异常残留自清理** | 上次崩溃遗留的档位，启动时自动恢复系统默认 |
| **降级保护** | 频率表完全读不到时，自动降级为"档位号"模式，仍可工作 |

## 工作原理

```text
                  ┌─────────────────────────────┐
                  │  proc_monitor.sh（独立进程）  │
                  │  logcat -b events            │
                  │   ├─ am_proc_start → 登记 PID │
                  │   └─ am_proc_died  → 记录时间 │
                  └──────────────┬──────────────┘
                                 │ 事件
                  ┌──────────────▼──────────────┐
                  │  service.sh（主守护，5秒循环） │
                  │  1. 校验目标 PID 存活          │
                  │  2. 游戏运行 → 写 min_pwrlevel │
                  │  3. 每轮只读校验，偏离才重写   │
                  │  4. 退出 8 秒 → 恢复默认档位   │
                  └──────────────┬──────────────┘
                                 │ 写入
                  ┌──────────────▼──────────────┐
                  │  /sys/class/kgsl/kgsl-3d0/   │
                  │      min_pwrlevel            │
                  └─────────────────────────────┘
```

### 接管通道对比（一加12 实测）

| 通道 | 写入后表现 | 结论 |
|---|---|---|
| `devfreq/min_freq` | 被 `msm-adreno-tz` governor 几秒内覆盖 | ❌ 不可靠 |
| **`min_pwrlevel`** | **13 分钟 26 次采样零覆盖，cur_freq 稳定** | ✅ 主通道 |

## 安装

```text
1. 在 KernelSU / Magisk / APatch 中刷入 g750-boost_v2.1.0.zip
2. 按音量键确认（音量上=安装 / 音量下=取消 / 15秒超时=安装）
3. 重启设备生效
4. 打开 WebUI：http://127.0.0.1:8778（或管理器内嵌 WebUI）
```

安装脚本自动识别处理器平台：

```text
- 当前平台: 8 Gen3 (Adreno750)
- 默认目标档位: 680MHz（安装后可在 WebUI 修改）
- 主通道 min_pwrlevel: 可用
```

## WebUI 使用

打开 `http://127.0.0.1:8778`：

### 状态面板（只读）

```text
平台        8 Gen3 (Adreno750)
实际地板    680 MHz        ← 内核当前真实地板
目标档位    680 MHz        ← 你设置的目标
当前频率    720 MHz        ← GPU 此刻运行频率
实际上限    903 MHz        ← 最高频率（默认不动）
游戏状态    游戏中 · com.netease.l22
温度        45 °C
```
### 档位设置

```text
[下拉框] 地板频率：903 / 834 / 770 / 720 / 680 / 629 / ... / 231 MHz
[下拉框] 上限频率：不限制（最高 903） / 903 / 834 / ... / 231 MHz
[保存档位] → 写入配置 → 守护进程 5 秒内热加载
```

- **地板**：游戏时 GPU 最低频率（你设置的值）
- **上限**：可选。默认"不限制（最高）"，即保持硬件最高档；若设置，则游戏时 GPU 不高于此值
- 上限会**常驻保护**，其他模块/应用把它拉低会被自动写回

**注意**：预设频率来自你设备的真实频率表。

## 技术细节

### 接管通道

- **地板主通道**：`/sys/class/kgsl/kgsl-3d0/min_pwrlevel`（档位号 = 频率表倒序 index）
- **上限主通道**：`/sys/class/kgsl/kgsl-3d0/max_pwrlevel`（0 = 最高档 = 不限制）
- **回退通道**：`/sys/class/kgsl/kgsl-3d0/devfreq/min_freq`、`max_freq`（无主通道节点时使用）

### 档位映射

```text
available_frequencies (倒序): 903 834 770 720 680 629 ... 231
档位号 (index):                0   1   2   3   4   5  ...  11

min_pwrlevel = 11 (默认)  → 地板 231MHz
min_pwrlevel = 4  (目标)  → 地板 680MHz
```

数字越小 = 地板越高。`max_pwrlevel`（0 = 最高档）始终不动。

### 恢复保证

- 启动保存系统默认档位（`num_pwrlevels - 1`）
- 游戏退出 / 模块禁用 / 卸载 / 进程异常（trap）全部恢复
- 崩溃残留：下次启动自动清理

### 最小开销设计

- 游戏运行中：每 5 秒**只读**一次 `min_pwrlevel`，与目标不符才重写
- 不遍历 `/proc`，只用 `pidof` 查白名单包名
- 事件驱动优先，轮询仅作兜底

## 跨厂商兼容性

本模块基于高通 KGSL 标准 sysfs 接口，**跨品牌通用**（一加 / OPPO / 真我 / 小米 / iQOO 等骁龙机型）。

源码查证（真我官方开源仓库 `realme-kernel-opensource`）：

```text
真我 GT7 Pro (SM8750):  drivers/devfreq/governor_msm_adreno_tz.c   ← 同一 governor
真我 GT8 Pro (SM8850):  qcom_base_ko.txt → msm_kgsl.ko             ← 同一驱动
                        canoe.dtsi / sun.dtsi → qcom,kgsl-3d0@3d00000  ← 同一节点
```

结论：GPU 驱动栈与一加/OPPO 完全相同，节点结构一致，可直接使用。

## 常见问题

**Q: 设置的是最低频率还是最高频率？**
A: 最低频率（地板）。最高频率默认不动。系统在地板以上自动调频。

**Q: 会不会增加很多功耗？**
A: 只在目标游戏运行期间抬高地板，退出即恢复。地板值可控（可在 WebUI 降低）。

**Q: 为什么 WebUI "当前频率"会变？**
A: 那是系统 governor 的实时调频值，正常现象。只要"实际地板"等于你的目标值即生效。

**Q: 切到微信小窗会掉频吗？**
A: 不会。只要目标游戏进程还在，地板就保持；8 秒迟滞仅用于游戏真正退出的判定。

**Q: 支持非骁龙设备吗？**
A: 不支持。本模块针对高通 Adreno GPU 的 KGSL 接口。
