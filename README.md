# G750 Boost — 游戏 GPU 地板档位模块

**作者**: 雨色  
**版本**: v2.2.11  
**适配**: SM8650 (8 Gen3 / Adreno750) · SM8750 (8 Elite / Adreno830) · SM8850 (8 Elite Gen5 / Adreno840)

---

## 这是什么

一个 KernelSU / Magisk / APatch 模块，用来**接管游戏运行时的 GPU 频率下限**。

手机 GPU 的默认调度很保守：即便你在跑游戏，系统仍会把频率压到很低来省电，结果就是**帧率忽高忽低、掉帧、触控迟滞**。G750 Boost 在检测到游戏运行时，把 GPU 的**地板档位**抬到你设定的值并锁住上限，系统 governor 在这个地板之上自由调频；游戏退出后自动恢复系统默认。

```text
游戏启动  →  三通道同步写入地板
游戏运行  →  每 0.3s 只读校验，偏离才重写；governor 在地板以上自由调频
游戏退出  →  8 秒迟滞后恢复系统默认档位
```

## 功能一览

### 1. 三通道地板接管

不只写一个节点，而是**三处同时写**，覆盖不同调频 App 与系统组件的接口：

| 通道 | 节点 | 单位 | 说明 |
|---|---|---|---|
| 主 | `/sys/class/kgsl/kgsl-3d0/min_pwrlevel` | 档位号 | 最可靠，实测长时间不被系统覆盖 |
| 软下限 | `<kgsl>/devfreq/min_freq` | Hz | 第三方调频 App 走这里 |
| 内核 | `/sys/kernel/gpu/gpu_min_clock` | MHz | msm_perf / 性能工具常用接口 |

节点不存在的平台**自动跳过**，不做空写。

### 2. 上限常驻护栏

防止游戏或原厂游戏栈（`opgs_daemon` 等）把上限拉低：

| 节点 | 单位 |
|---|---|
| `max_pwrlevel` | 档位号 |
| `max_gpuclk` | Hz |
| `/sys/kernel/gpu/gpu_max_clock` | MHz |
| `<kgsl>/devfreq/max_freq` | Hz |

四路每 0.3 秒检测，被拉低后 0.3 秒内拉回。

### 3. 档位可自定义（WebUI）

- 下拉框列出**设备真实档位**，每项标注档位号
- **保存即吸附**：你选的 MHz 若不在设备频表上，自动落到最近的可用档位，并回显「生效值 + 档位号」
- 配置值与设备档位不一致时给出 ⚠ 提示
- 游戏运行中改动 0.3 秒内应用；非游戏态不写地板，进游戏后生效

### 4. 配置目标与生效值分离

WebUI 状态区同时展示三组值，一眼看出是"配置没生效"还是"被谁改了"：

- **配置目标** — 读配置文件，非游戏态也准确
- **当前生效** — 运行态缓存，仅游戏态刷新
- **硬件实际** — 直接读 sysfs

### 5. 液态玻璃 WebUI

自适应手机单列 / 平板双栏，含浅色 / 暗色 / 跟随系统三态主题。

**壁纸支持**（系统相册选图）：

- 走 **root 直读**：`_id` → `content query` 解析真实路径 → `cp` 进模块 → magic 校验 → 原子替换
- 失败自动回落到 `content read` 流式读取 → FileReader 直传 → canvas 压缩
- 壁纸透明度可调（`wall_opacity`）
- **玻璃透明度可调**（`wall_glass`）：统一驱动卡片 / 日志区 / 输入框 / 浮动按钮的玻璃层
- **玻璃模糊可调**（`wall_blur`）：0–40px，0 = 完全无模糊

**分页导航**：首页（状态 + 档位配置 + 日志）与壁纸设置分为两个独立页面，底栏导航切换并高亮当前页。

### 6. 游戏白名单

编辑 `/data/adb/modules/g750-boost/games.txt`，一行一个包名。

支持**前台 / 后台 / 小窗**运行，游戏进程存活期间地板始终生效。

### 7. 可靠性与安全性

- **服务自愈守护**：`webdaemon.sh` 每 10 秒探活，死亡即拉起（带失败退避）；模块 disable/remove 时绝不拉起
- **恢复保证**：启动时保存系统默认档位；退出 / 禁用 / 卸载 / 进程异常（trap）全部恢复；崩溃残留下次启动自动清理
- **热路径零 fork**：节点读写 / 配置读取 / 进程校验全走 shell 内建，游戏期 0.3s 一轮 ≈ 73μs，CPU 占用 <0.02%
- **写后回读自检**：被驱动丢弃时输出 `WARN floor write rejected`
- **路径注入防护**：外部路径参数 base64url token 化；`_id` 严格数字白名单；后端三重路径校验 + JPEG/PNG/WEBP magic 校验
- **失败可见**：WebUI 写入失败时直接回显诊断尾部，无需 root 读日志

## 技术细节

### 档位映射

`available_frequencies` 的 index = pwrlevel。模块先把频表**强制降序归一化**（不同 SoC / devfreq 表顺序不保证），再用 `num_pwrlevels` 做条目数对齐校验。

- **地板**：目标频率 → 选择 **≥ 目标的最小档位**（如 700 → 720）
- **上限**：目标频率 → 选择 **≤ 目标的最大档位**（如 400 → 366）
- 保存时写入的是**吸附后**的值，WebUI 显示的永远是设备真实档位

### 平台自适配

识别优先级：**GPU 硬件型号**（`gpu_model`，最可靠）> `ro.soc.model` > `ro.board.platform`。

厂商 ROM 的 `ro.soc.model` 命名可能不准（8e5 曾被写成 SM8750），所以以 GPU 实际型号为首要判据。

### 节点路径缓存

首次探测后把 4 个 sysfs 路径缓存到 `config/gpu_paths.conf`，后续直接读缓存（缓存的是**路径**，不是频率值）。路径失效时自动重新探测。

**频率表始终实时读内核节点**，从不缓存 —— 内核更新频表后立即生效。

### 8 Elite Gen5 特别说明

8e5 上 `devfreq` 设备虽注册但**无频率节点**（gen8 把调频决策移到 GMU DCVS，DCVS 节点全部只读）。代码按"节点文件存在"探测，不存在自动跳过。`min_pwrlevel` / `min_clock_mhz` / `gpu_min_clock` 在 8e5 上指向**同一后端**，写一个另两个跟随。
